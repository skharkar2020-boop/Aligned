# Scientific task maintainer notes

## Data provenance

`expression_matrix.csv` and `sample_metadata.csv` (identical copies in
`environment/data/` and `tests/data/`) are synthetic, generated by
`../data_generation/generate_data.py` (deterministic -- every RNG is seeded
via a SHA256-based `stable_seed`, not Python's `hash()`, so the script
reproduces byte-identical output across runs and processes). That script
also writes `../data_generation/private/ground_truth.json`, an
authoring-only file carrying the full per-cohort and pooled ranked DE
tables computed from the correct, ID-based, per-cohort-reconciled
analysis; it is **not** copied into `environment/data/`, `tests/data/`, or
either Docker build context, and must never be. `environment/data/` also
ships `prior_pilot_report.md`, a small agent-visible file (see "The prior
pilot report" below).

`environment/data/pipeline/` (the code the agent actually runs and fixes)
is hand-written, not generated, and is public/agent-visible by design.

## Design history

This task went through five authoring rounds. The first two rounds
(single-cohort alignment bugs, then a batch-confound judgment, then a
small-sample variance-moderation judgment) each drew the same `task-review`
`difficult` finding: the task read as "locate straightforward defects,"
not something requiring genuine domain expertise. Both individual
additions were real, professionally-relevant knowledge, but each was a
single, well-known rule -- once you know it, applying it is mechanical.

The third round was a structural rebuild: two independent cohorts that
each produce a complete, individually defensible, non-crashing analysis
and disagree, with a `confounded_cohort` output field asking the agent to
say which one wasn't trustworthy. This still drew the same `difficult`
finding: the resolution had collapsed into "one cohort is obviously
confounded, the other is obviously clean," which is a single fact to
discover, not an ongoing judgment call to defend.

The fourth round kept everything about the third round's premise -- the
buggy pipeline, the two-cohort structure, the requirement to rehabilitate
an existing analysis -- but redesigned *what the two cohorts actually
show* so that neither can be discarded wholesale:

- The true gene now has a **real effect in both cohorts, same direction**,
  strong in `cohort1` and weaker-but-still-real in `cohort2` (ordinary,
  expected effect-size heterogeneity, not "null in one cohort").
- The competing technical-artifact gene has **no real effect in either
  cohort**; its apparent signal is driven by a **latent** factor (never
  written to any public column) that happens to correlate with condition
  only within `cohort2`. Several other unlabeled "sentinel" genes load on
  the same latent factor, so the technical axis is recoverable from
  expression structure (genes that move together, confined to one
  cohort), not from a labeled column.
- A third gene has a real, consistent effect in *both* cohorts, similar
  magnitude in each -- but smaller and with weaker overall evidence than
  the true gene. It exists so "most consistent across cohorts" and "most
  defensible answer" are not always the same gene, forcing an explicit
  evidence-strength tradeoff.
- Naive pooled DE, trusting a single cohort, and a sign-blind
  meta-analysis strategy each land on a different plausible (and
  different from correct) answer -- see the calibration table below. None
  of the four scenarios tested is a coding error; each is a real,
  internally consistent, non-crashing statistical analysis that fails for
  a different reason.
- The output schema changed to match: `confounded_cohort` is gone.
  `analysis_strategy`, `cohort1_log2_fold_change`,
  `cohort2_log2_fold_change`, `heterogeneity_assessment`,
  `rejected_competing_gene`, and `rationale` are new.
  `verified_matching_sample_ids` is now a boolean, not a count.

The fifth (current) round followed a blind trial of round 4 (a fresh
subagent, given only `instruction.md` and the agent-visible files, no
knowledge of this design): it correctly fixed both code bugs, correctly
ran the per-cohort replication logic, and correctly named the true gene --
the reasoning that was supposed to be the hard part wasn't actually hard
in practice. Two distinct problems came out of that trial, addressed
separately:

1. **Contract bugs, not difficulty.** `analysis_strategy`'s neutral codes
   (`strategy_a`..`e`, from a prior round's anti-cheat rename) had no
   definitions anywhere the agent could see, so there was no reasoning
   path from "I did per-cohort replication" to "therefore `strategy_e`" --
   it was a coin flip regardless of skill. Similarly, nothing said which
   cohort's numbers belonged in the top-level `log2_fold_change`/
   `adjusted_p_value` fields. Both are now stated explicitly in
   `instruction.md` (neutral method-shape descriptions for each code; the
   headline fields are the nominated gene's own result from its
   stronger-evidence cohort). Neither of these reveals which answer is
   correct -- they just make the contract honestly checkable, per this
   repo's own standard: the shape must be nameable, not the method.
2. **The candidate genes weren't actually forcing hard tradeoffs.**
   `CONSISTENCY_GENE` lost to `TRUE_GENE` by ~1000x on combined evidence
   (not a close call); `CONFOUND_GENE`'s own cohort1 result was a clean,
   unambiguous null (p~0.15); and the latent-factor mechanism was never
   actually load-bearing in practice (the blind trial solved the whole
   task via per-cohort replication alone, never needing to notice the
   sentinel genes at all). Round 5 recalibrates and adds:
   - `CONSISTENCY_GENE` tightened to a genuine ~5-10x combined-evidence
     gap against `TRUE_GENE` (was ~1000x) -- still loses, but a
     "most-consistent-across-cohorts" heuristic is now a real temptation,
     not a trivial miss.
   - `CONFOUND_GENE` recalibrated so its own cohort1 result now clears
     nominal p<0.05 on its own -- but with the *opposite* sign from its
     overwhelming cohort2 effect. A same-signed-replication check (not
     just a significance check) is now required to reject it correctly.
   - `GHOST_REPLICATOR` (new): a third gene that clears the same
     nominal-significance-both-cohorts bar as `TRUE_GENE` and
     `CONSISTENCY_GENE`, with a real (small) biological effect in both
     cohorts, but whose cohort2 evidence is also partly inflated by the
     same latent factor as `CONFOUND_GENE`. It never wins on combined
     evidence, but it's a plausible-looking distractor for a pooled-DE or
     cohort2-only strategy (large cohort2 fold-change).
   - `REAL_HETEROGENEITY_GENE` (new): independently significant in each
     cohort on its own, but with opposite sign between cohorts -- and, on
     purpose, no loading on the latent factor at all. It fails the
     same-sign replication check for a genuinely different reason than
     `CONFOUND_GENE` does (real biological heterogeneity that reverses
     sign, not a technical artifact), so the task now contains a case
     where "failed replication" does not imply "technical artifact" --
     guarding against over-applying the lesson from `CONFOUND_GENE`.
   A correlation-based "is this candidate part of the same technical
   module as the rejected gene" diagnostic was explored as a formal,
   required disqualifier step but abandoned: at n=6 per cohort-condition
   group, pairwise gene-gene correlation has too much sampling noise
   (SE ~1/sqrt(n-3) ~ 0.33) to reliably separate a genuinely-entangled
   gene from an unrelated one, even averaged across all 7 latent-factor
   family members. Forcing it into the deterministic verifier would have
   reintroduced the exact fragile-mechanism problem `VARIANCE_TRAP` and
   the `batch2`/`sample_02` device were retired for in round 3. The
   sentinel/latent-factor structure is still present in the data and
   still a legitimate thing for a thorough agent to discover and cite in
   `rationale`, but citing it is optional -- it is not a required,
   deterministically-graded step (see below for the one thing about
   `rationale` that *is* content-graded).
   The existing resolution algorithm (per-cohort nominal replication +
   Fisher-combined-p tie-break among survivors) needed **no changes** to
   correctly resolve all five competing genes against the recalibrated
   data -- re-verified against the actual 300-gene panel, not projected.

3. **`analysis_strategy` exact-match relaxed, then a narrower gap closed
   in its place.** Three independent `task-review` runs kept flagging the
   same thing even across two genuine content fixes (softened
   `instruction.md` wording, corrected `strategy_e`'s own definition to
   include the sign-agreement requirement it had been missing): grading
   `analysis_strategy == "strategy_e"` exactly, on top of every other
   field already being checked against the correct answer, amounted to an
   undisclosed requirement to guess this task's internal label for
   correct reasoning rather than to actually reason correctly. The exact
   match was dropped from `CHECKS` (the comparison function itself stays
   in `tests/test_outputs.py`, undeleted, for anyone reading a submitted
   result by hand); `analysis_strategy` is still required to be one of
   the five valid codes (a schema check), just not scored against the
   reference value.

   Dropping it exposed a real regression, caught before shipping by
   deliberately constructing the failure case rather than assuming it
   away: a **sign-blind Fisher combined-p meta-analysis** -- an unsound
   method that never checks whether the two cohorts agree on effect
   *direction* before combining their p-values -- happens to land on the
   correct `top_gene` on this locked dataset purely because that gene's
   two p-values are each individually smaller than the rejected
   competitor's. With `analysis_strategy` no longer scored, nothing else
   in the verifier caught that the method itself was unsound; the
   constructed scenario passed the fully-relaxed verifier at 8/8.

   The fix is a narrower, targeted content check
   (`test_rationale_addresses_effect_direction`): `rationale` must
   explicitly state that the rejected competing gene's own effect points
   the opposite direction between cohorts, not merely cite significance.
   A genuinely sign-aware analysis has a basis to make that specific
   claim; a sign-blind one does not, and its honest rationale ("combined
   p-values without checking sign agreement") describes its *method*
   without ever asserting the rejected gene is actually opposite-signed --
   confirmed against the constructed sign-blind scenario, which fails
   this check (8/9) even though it passes every numeric one. This is a
   deliberate, documented exception to "rationale is presence-only, never
   content-graded" (the rest of `rationale` still isn't): it's a
   substring-matching heuristic over a list of accepted phrasings
   (`DIRECTION_MISMATCH_PHRASES` in `tests/test_outputs.py`, broadened to
   ~50 natural phrasings to reduce false-negative risk), not semantic
   understanding -- it can't verify the reasoning was sound, only that
   the one load-bearing claim was actually made. Because the exact
   phrase list isn't agent-visible (`tests/` is excluded from the Docker
   image, same as the reason `analysis_strategy`'s exact match had to go),
   `instruction.md` discloses the requirement itself in plain language
   ("if the rejected candidate's own treatment effect points in a
   different direction between the two cohorts, the rationale should say
   so explicitly") without revealing which gene that turns out to be.

## The prior pilot report

`environment/data/prior_pilot_report.md` is a short, agent-visible file
describing an earlier, much smaller, single-cohort pilot (no confirmatory
cohort) -- deliberately without naming a gene or giving any number
specific enough to identify one. An earlier design named the correct gene
outright, with only the accompanying numbers made stale (the idea being
that copying those numbers would fail the numeric tolerance checks even
though the gene name was right); `task-review`'s `anti_cheat_robustness`
criterion correctly caught this as a real leak regardless of the numbers
being wrong -- naming the gene at all hands over the task's central
judgment call. The current version establishes the same "don't trust
historical claims blindly, reproduce independently" narrative purely
through methodology caveats (small n, no confirmatory cohort, summary
data not retained), with nothing in the file that narrows down which of
the 300 genes is the intended answer. Generated fresh alongside the rest
of the public data (`write_prior_report` in `generate_data.py`), and no
longer depends on the locked ground truth at all, unlike the retired
gene-naming version.

## Bug-layer design and empirical verification

Three compounding code defects are baked into `environment/data/pipeline/`,
plus a latent cross-cohort confound the pipeline never handles at all. All
of the following was verified by actually running the pipeline and
reference code under two real, separately-installed dependency sets, not
by inspection:

1. **Warm-up crash** (`pipeline/io.py`): `counts.astype(np.float)`. Verified
   this raises `AttributeError: module 'numpy' has no attribute 'float'`
   under numpy==1.26.4 (the pinned runtime version) and does not under
   numpy<1.24.
2. **Silent misalignment** (`pipeline/qc.py`): the QC report's
   `sort_values("sample_id")` lexicographically reorders string IDs
   (`sample_10` sorts before `sample_2`), and that reordered table becomes
   the canonical metadata for the rest of the run.
3. **Hard-negative merge** (`pipeline/align.py`): concatenates expression
   and (now-reordered) metadata positionally after resetting both indices,
   branching on the installed pandas major version. Verified with real
   pandas 1.5.3 and 2.2.3 (both installed from a local `pip download
   --platform manylinux2014_x86_64 --python-version 3.11` wheelhouse,
   offline): "upgrading" pandas after fixing the crash changes the wrong
   answer (a different unrelated null gene) rather than fixing it.
4. **Latent cross-cohort confound, never handled by the pipeline**
   (data-level, not a pipeline bug): a continuous latent factor `Z`
   (`DELTA_Z=1.2`, `Z_SD=0.3` in `generate_data.py`), defined only for
   `cohort2` samples, partially correlated with condition there
   (mean-separated but noisy, not a deterministic label). The competing
   gene loads heavily on `Z` (`z_loading=2.5`), as does `GHOST_REPLICATOR`
   more weakly (`z_loading=0.8`, on top of its own small real effect); six
   additional "sentinel" genes load on the same factor with smaller,
   mixed-sign loadings, so it covaries with (and is inferable from)
   several other genes within `cohort2`, never from a labeled column. The
   pipeline itself has no cohort or latent-factor awareness at all and
   pools all 24 samples by default once alignment is fixed.

Difficulty layer B (misleading assertion): `run_pipeline.py`'s
`assert combined.shape[0] == metadata.shape[0]` is real, present, and
passes in every misaligned scenario tested below -- it only checks row
*count*. Layer C (near-miss/plausible-but-wrong strategies): naive
pooling, trusting `cohort2` alone, a sign-blind combined-p meta-analysis,
and preferring consistency over evidence strength are each a complete,
non-crashing, internally consistent analysis of correctly-ID-aligned data
that names a different (and, for most of them, wrong) top gene -- see the
table below. Layer D: `verified_matching_sample_ids` is not part of the
shipped pipeline's output at all; it must be added by whoever fixes it,
and is a boolean (`true`) regardless of which gene ends up reported.

Every wrong scenario fails at least three of the verifier's checks, each
for a different reason: naive pooling now fails `top_gene` outright (not
just the numeric fields, as in round 4); trusting `cohort2` alone fails on
`top_gene`, both cohort fields, `heterogeneity_assessment`, and
`rejected_competing_gene` together; preferring consistency over strength
fails `top_gene` and every numeric field despite reporting a real,
legitimately-replicating gene; and reporting `REAL_HETEROGENEITY_GENE` in
either output field fails outright even though its own per-cohort
significance is genuine and strong.

## Open items for the human author

- `instruction.md` and `task.toml` are both complete -- the author wrote
  `difficulty_explanation`/`solution_explanation`/`verification_explanation`
  in their own voice, and `expert_time_estimate_hours` is set to `7.0`
  with the reasoning behind that number in an inline comment. No
  `REPLACE:` placeholders remain in either file.
- `task-fixer` and `task-review` have been run locally (Docker images
  build successfully, both well under the size limit). The last full run
  was FAIL, 24/30 PASS. Since that run, the following of its findings have
  been addressed in code/docs, but not yet re-verified by an actual fresh
  `task-review` pass:
  - `well_specified` / `outcome_verified` / `test_instruction_alignment`
    (three ratings, one underlying concern): the verifier previously
    required `analysis_strategy == strategy_e` specifically while
    `instruction.md` presented all five codes as a closed vocabulary to
    *describe* whatever approach was used, not as five equally-correct
    options -- an undisclosed method requirement layered on an otherwise
    fully outcome-graded task. Resolved by dropping the exact match (see
    "Two distinct problems", item 3, above) and replacing it with a
    narrower, disclosed content check on `rationale`.
  - `difficulty_explanation_quality` / `verification_explanation_quality`:
    the author's prose now explicitly states that the data are
    synthetic/deterministically generated, names the real-world
    practitioner role, and justifies the specific numeric tolerances
    (`LOG2FC_ABS_TOL=0.2`, `ADJ_P_LOG10_TOL=3.0`, `ADJ_P_MAX_FOR_SIGNIFICANT=5e-4`)
    against the wrong-scenario margins in the calibration table above --
    see `task.toml`'s `difficulty_explanation` and
    `verification_explanation`. `verification_explanation` has also been
    corrected to describe the current `analysis_strategy`/`rationale`
    grading mechanism accurately rather than the retired exact-match one.
  - Still genuinely open, deferred to a future round by explicit author
    decision: the `difficult` rating itself (a round-6 recalibration
    question, not a contract-gap fix like the two above).
- Two blind-trial screens (a subagent with no knowledge of this design,
  given only `instruction.md` and the agent-visible files) have been run:
  one after round 4 (passed the science, failed only on since-fixed
  contract ambiguities) and one after round 5 (failed genuinely, on the
  tightened `CONSISTENCY_GENE` evidence-strength tradeoff). Neither is a
  substitute for the real Harbor campaign and `trajectory-review`, which
  have not been run yet.
