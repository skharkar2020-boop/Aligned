# Scientific task maintainer notes

## Data provenance

`expression_matrix.csv` and `sample_metadata.csv` (identical copies in
`environment/data/` and `tests/data/`) are synthetic, generated by
`../data_generation/generate_data.py` (deterministic -- every RNG is seeded
via a SHA256-based `stable_seed`, not Python's `hash()`, so the script
reproduces byte-identical output across runs and processes). That script
also writes `../data_generation/private/ground_truth.json`, an
authoring-only file carrying the full per-cohort and pooled ranked DE
tables computed from the correct, ID-based, per-cohort-reconciled
analysis; it is **not** copied into `environment/data/`, `tests/data/`, or
either Docker build context, and must never be. `environment/data/` also
ships `prior_pilot_report.md`, a small agent-visible file (see "The prior
pilot report" below).

`environment/data/pipeline/` (the code the agent actually runs and fixes)
is hand-written, not generated, and is public/agent-visible by design.

## Design history

This task went through five authoring rounds. The first two rounds
(single-cohort alignment bugs, then a batch-confound judgment, then a
small-sample variance-moderation judgment) each drew the same `task-review`
`difficult` finding: the task read as "locate straightforward defects,"
not something requiring genuine domain expertise. Both individual
additions were real, professionally-relevant knowledge, but each was a
single, well-known rule -- once you know it, applying it is mechanical.

The third round was a structural rebuild: two independent cohorts that
each produce a complete, individually defensible, non-crashing analysis
and disagree, with a `confounded_cohort` output field asking the agent to
say which one wasn't trustworthy. This still drew the same `difficult`
finding: the resolution had collapsed into "one cohort is obviously
confounded, the other is obviously clean," which is a single fact to
discover, not an ongoing judgment call to defend.

The fourth round kept everything about the third round's premise -- the
buggy pipeline, the two-cohort structure, the requirement to rehabilitate
an existing analysis -- but redesigned *what the two cohorts actually
show* so that neither can be discarded wholesale:

- The true gene now has a **real effect in both cohorts, same direction**,
  strong in `cohort1` and weaker-but-still-real in `cohort2` (ordinary,
  expected effect-size heterogeneity, not "null in one cohort").
- The competing technical-artifact gene has **no real effect in either
  cohort**; its apparent signal is driven by a **latent** factor (never
  written to any public column) that happens to correlate with condition
  only within `cohort2`. Several other unlabeled "sentinel" genes load on
  the same latent factor, so the technical axis is recoverable from
  expression structure (genes that move together, confined to one
  cohort), not from a labeled column.
- A third gene has a real, consistent effect in *both* cohorts, similar
  magnitude in each -- but smaller and with weaker overall evidence than
  the true gene. It exists so "most consistent across cohorts" and "most
  defensible answer" are not always the same gene, forcing an explicit
  evidence-strength tradeoff.
- Naive pooled DE, trusting a single cohort, and a sign-blind
  meta-analysis strategy each land on a different plausible (and
  different from correct) answer -- see the calibration table below. None
  of the four scenarios tested is a coding error; each is a real,
  internally consistent, non-crashing statistical analysis that fails for
  a different reason.
- The output schema changed to match: `confounded_cohort` is gone.
  `analysis_strategy`, `cohort1_log2_fold_change`,
  `cohort2_log2_fold_change`, `heterogeneity_assessment`,
  `rejected_competing_gene`, and `rationale` are new.
  `verified_matching_sample_ids` is now a boolean, not a count.

The fifth (current) round followed a blind trial of round 4 (a fresh
subagent, given only `instruction.md` and the agent-visible files, no
knowledge of this design): it correctly fixed both code bugs, correctly
ran the per-cohort replication logic, and correctly named the true gene --
the reasoning that was supposed to be the hard part wasn't actually hard
in practice. Two distinct problems came out of that trial, addressed
separately:

1. **Contract bugs, not difficulty.** `analysis_strategy`'s neutral codes
   (`strategy_a`..`e`, from a prior round's anti-cheat rename) had no
   definitions anywhere the agent could see, so there was no reasoning
   path from "I did per-cohort replication" to "therefore `strategy_e`" --
   it was a coin flip regardless of skill. Similarly, nothing said which
   cohort's numbers belonged in the top-level `log2_fold_change`/
   `adjusted_p_value` fields. Both are now stated explicitly in
   `instruction.md` (neutral method-shape descriptions for each code; the
   headline fields are the nominated gene's own result from its
   stronger-evidence cohort). Neither of these reveals which answer is
   correct -- they just make the contract honestly checkable, per this
   repo's own standard: the shape must be nameable, not the method.
2. **The candidate genes weren't actually forcing hard tradeoffs.**
   `CONSISTENCY_GENE` lost to `TRUE_GENE` by ~1000x on combined evidence
   (not a close call); `CONFOUND_GENE`'s own cohort1 result was a clean,
   unambiguous null (p~0.15); and the latent-factor mechanism was never
   actually load-bearing in practice (the blind trial solved the whole
   task via per-cohort replication alone, never needing to notice the
   sentinel genes at all). Round 5 recalibrates and adds:
   - `CONSISTENCY_GENE` tightened to a genuine ~5-10x combined-evidence
     gap against `TRUE_GENE` (was ~1000x) -- still loses, but a
     "most-consistent-across-cohorts" heuristic is now a real temptation,
     not a trivial miss.
   - `CONFOUND_GENE` recalibrated so its own cohort1 result now clears
     nominal p<0.05 on its own -- but with the *opposite* sign from its
     overwhelming cohort2 effect. A same-signed-replication check (not
     just a significance check) is now required to reject it correctly.
   - `GHOST_REPLICATOR` (new): a third gene that clears the same
     nominal-significance-both-cohorts bar as `TRUE_GENE` and
     `CONSISTENCY_GENE`, with a real (small) biological effect in both
     cohorts, but whose cohort2 evidence is also partly inflated by the
     same latent factor as `CONFOUND_GENE`. It never wins on combined
     evidence, but it's a plausible-looking distractor for a pooled-DE or
     cohort2-only strategy (large cohort2 fold-change).
   - `REAL_HETEROGENEITY_GENE` (new): independently significant in each
     cohort on its own, but with opposite sign between cohorts -- and, on
     purpose, no loading on the latent factor at all. It fails the
     same-sign replication check for a genuinely different reason than
     `CONFOUND_GENE` does (real biological heterogeneity that reverses
     sign, not a technical artifact), so the task now contains a case
     where "failed replication" does not imply "technical artifact" --
     guarding against over-applying the lesson from `CONFOUND_GENE`.
   A correlation-based "is this candidate part of the same technical
   module as the rejected gene" diagnostic was explored as a formal,
   required disqualifier step but abandoned: at n=6 per cohort-condition
   group, pairwise gene-gene correlation has too much sampling noise
   (SE ~1/sqrt(n-3) ~ 0.33) to reliably separate a genuinely-entangled
   gene from an unrelated one, even averaged across all 7 latent-factor
   family members. Forcing it into the deterministic verifier would have
   reintroduced the exact fragile-mechanism problem `VARIANCE_TRAP` and
   the `batch2`/`sample_02` device were retired for in round 3. The
   sentinel/latent-factor structure is still present in the data and
   still a legitimate thing for a thorough agent to discover and cite in
   `rationale`, but citing it is optional -- it is not a required,
   deterministically-graded step (see below for the one thing about
   `rationale` that *is* content-graded).
   The existing resolution algorithm (per-cohort nominal replication +
   Fisher-combined-p tie-break among survivors) needed **no changes** to
   correctly resolve all five competing genes against the recalibrated
   data -- re-verified against the actual 300-gene panel, not projected.

3. **`analysis_strategy` exact-match relaxed, then a narrower gap closed
   in its place.** Three independent `task-review` runs kept flagging the
   same thing even across two genuine content fixes (softened
   `instruction.md` wording, corrected `strategy_e`'s own definition to
   include the sign-agreement requirement it had been missing): grading
   `analysis_strategy == "strategy_e"` exactly, on top of every other
   field already being checked against the correct answer, amounted to an
   undisclosed requirement to guess this task's internal label for
   correct reasoning rather than to actually reason correctly. The exact
   match was dropped from `CHECKS` (the comparison function itself stays
   in `tests/test_outputs.py`, undeleted, for anyone reading a submitted
   result by hand); `analysis_strategy` is still required to be one of
   the five valid codes (a schema check), just not scored against the
   reference value.

   Dropping it exposed a real regression, caught before shipping by
   deliberately constructing the failure case rather than assuming it
   away: a **sign-blind Fisher combined-p meta-analysis** -- an unsound
   method that never checks whether the two cohorts agree on effect
   *direction* before combining their p-values -- happens to land on the
   correct `top_gene` on this locked dataset purely because that gene's
   two p-values are each individually smaller than the rejected
   competitor's. With `analysis_strategy` no longer scored, nothing else
   in the verifier caught that the method itself was unsound; the
   constructed scenario passed the fully-relaxed verifier at 8/8.

   The fix is a narrower, targeted content check
   (`test_rationale_addresses_effect_direction`): `rationale` must
   explicitly state that the rejected competing gene's own effect points
   the opposite direction between cohorts, not merely cite significance.
   A genuinely sign-aware analysis has a basis to make that specific
   claim; a sign-blind one does not, and its honest rationale ("combined
   p-values without checking sign agreement") describes its *method*
   without ever asserting the rejected gene is actually opposite-signed --
   confirmed against the constructed sign-blind scenario, which fails
   this check (8/9) even though it passes every numeric one. This is a
   deliberate, documented exception to "rationale is presence-only, never
   content-graded" (the rest of `rationale` still isn't): it's a
   substring-matching heuristic over a list of accepted phrasings
   (`DIRECTION_MISMATCH_PHRASES` in `tests/test_outputs.py`, broadened to
   ~50 natural phrasings to reduce false-negative risk), not semantic
   understanding -- it can't verify the reasoning was sound, only that
   the one load-bearing claim was actually made. Because the exact
   phrase list isn't agent-visible (`tests/` is excluded from the Docker
   image, same as the reason `analysis_strategy`'s exact match had to go),
   `instruction.md` discloses the requirement itself in plain language
   ("if the rejected candidate's own treatment effect points in a
   different direction between the two cohorts, the rationale should say
   so explicitly") without revealing which gene that turns out to be.

## The prior pilot report

`environment/data/prior_pilot_report.md` is a short, agent-visible file
describing an earlier, much smaller, single-cohort pilot (no confirmatory
cohort) -- deliberately without naming a gene or giving any number
specific enough to identify one. An earlier design named the correct gene
outright, with only the accompanying numbers made stale (the idea being
that copying those numbers would fail the numeric tolerance checks even
though the gene name was right); `task-review`'s `anti_cheat_robustness`
criterion correctly caught this as a real leak regardless of the numbers
being wrong -- naming the gene at all hands over the task's central
judgment call. The current version establishes the same "don't trust
historical claims blindly, reproduce independently" narrative purely
through methodology caveats (small n, no confirmatory cohort, summary
data not retained), with nothing in the file that narrows down which of
the 300 genes is the intended answer. Generated fresh alongside the rest
of the public data (`write_prior_report` in `generate_data.py`), and no
longer depends on the locked ground truth at all, unlike the retired
gene-naming version.

## Bug-layer design and empirical verification

Three compounding code defects are baked into `environment/data/pipeline/`,
plus a latent cross-cohort confound the pipeline never handles at all. All
of the following was verified by actually running the pipeline and
reference code under two real, separately-installed dependency sets, not
by inspection:

1. **Warm-up crash** (`pipeline/io.py`): `counts.astype(np.float)`. Verified
   this raises `AttributeError: module 'numpy' has no attribute 'float'`
   under numpy==1.26.4 (the pinned runtime version) and does not under
   numpy<1.24.
2. **Silent misalignment** (`pipeline/qc.py`): the QC report's
   `sort_values("sample_id")` lexicographically reorders string IDs
   (`sample_10` sorts before `sample_2`), and that reordered table becomes
   the canonical metadata for the rest of the run.
3. **Hard-negative merge** (`pipeline/align.py`): concatenates expression
   and (now-reordered) metadata positionally after resetting both indices,
   branching on the installed pandas major version. Verified with real
   pandas 1.5.3 and 2.2.3 (both installed from a local `pip download
   --platform manylinux2014_x86_64 --python-version 3.11` wheelhouse,
   offline): "upgrading" pandas after fixing the crash changes the wrong
   answer (a different unrelated null gene) rather than fixing it.
4. **Latent cross-cohort confound, never handled by the pipeline**
   (data-level, not a pipeline bug): a continuous latent factor `Z`
   (`DELTA_Z=1.2`, `Z_SD=0.3` in `generate_data.py`), defined only for
   `cohort2` samples, partially correlated with condition there
   (mean-separated but noisy, not a deterministic label). The competing
   gene loads heavily on `Z` (`z_loading=2.5`), as does `GHOST_REPLICATOR`
   more weakly (`z_loading=0.8`, on top of its own small real effect); six
   additional "sentinel" genes load on the same factor with smaller,
   mixed-sign loadings, so it covaries with (and is inferable from)
   several other genes within `cohort2`, never from a labeled column. The
   pipeline itself has no cohort or latent-factor awareness at all and
   pools all 24 samples by default once alignment is fixed.

Difficulty layer B (misleading assertion): `run_pipeline.py`'s
`assert combined.shape[0] == metadata.shape[0]` is real, present, and
passes in every misaligned scenario tested below -- it only checks row
*count*. Layer C (near-miss/plausible-but-wrong strategies): naive
pooling, trusting `cohort2` alone, a sign-blind combined-p meta-analysis,
and preferring consistency over evidence strength are each a complete,
non-crashing, internally consistent analysis of correctly-ID-aligned data
that names a different (and, for most of them, wrong) top gene -- see the
table below. Layer D: `verified_matching_sample_ids` is not part of the
shipped pipeline's output at all; it must be added by whoever fixes it,
and is a boolean (`true`) regardless of which gene ends up reported.

## Round 6: replacing the nominal-vs-BH trap with fragile-vs-robust replication

The disclosed nominal-vs-BH fix above did not hold up: a real Harbor
campaign run against it (Oracle PASS; 4/4 Claude Opus, 4/4 Codex, all real
task failures; 4/4 Gemini trials never got past Antigravity CLI
authentication and don't count as task evidence either way) still had every
meaningful trial converge on `CONSISTENCY_GENE`/`GENE_204`, via a real,
internally consistent methodology (requiring BH-FDR significance, not just
nominal, in the confirmatory cohort). `trajectory-review` classified all 8
as non-genuine failures again and recommended loosening the verifier a
second time. That recommendation was rejected for the same reason as
before -- it would delete the task's central judgment call, not fix a
contract gap -- but the repeat 8/8 convergence, on a mechanism that had
already been disclosed once, was itself evidence that the underlying trap
was not scientifically airtight: *any* defensible BH-FDR-in-both-cohorts
reading could still prefer `GENE_204`, disclosure or not. The trap needed to
be rebuilt on a criterion that is actually correct science, not one
specific convention choice among several defensible ones.

**What was tried and rejected first.** The original plan was to make
`CONSISTENCY_GENE`'s apparent replication depend on the same latent
covariance factor already used for `CONFOUND_GENE` (a small partial
`z_loading`, recoverable in principle from genes that move together within
`cohort2`). This was tested numerically before touching any code: with only
6 samples per cohort-condition group and 6 sentinel genes to correlate
against, a PCA-based residualized-factor-recovery diagnostic could not
reliably separate the real positive control (`GHOST_REPLICATOR`, actual
`z_loading=0.8`) from unrelated noise-floor genes. A trap that isn't
actually recoverable from the supplied data at this sample size is not a
scientific judgment call, it's a coin flip dressed up as one -- so this
mechanism was abandoned before any generator code was touched, per the same
"verify numerically before implementing" standard the rest of this file
documents.

**The adopted mechanism: fragile vs. robust replication.**
`CONSISTENCY_GENE`'s `cohort2`-treated group now gets a uniform base effect
across all 6 samples, *plus* an extra additive log2FC boost
(`INFLUENTIAL_EXTRA_LOG2FC=1.8`) concentrated in only
`N_INFLUENTIAL_SAMPLES=2` of those 6 samples (chosen deterministically via
`stable_seed("consistency_influential_samples")`, not tied to any public
column). With all 6 samples included, this still clears ordinary Welch
nominal significance, BH-FDR at its own discovery cohort, same-sign
same-magnitude cross-cohort consistency, and nonparametric (Mann-Whitney U)
testing -- every "ordinary" method a careful agent would reach for finds it
a real, legitimate-looking hit. But a leave-one-out robustness check within
the treated group -- drop each treated sample once, recompute the p-value
against the full control group, keep the worst (largest) p-value seen --
reveals that its `cohort2` significance evaporates (worst-case p rises well
above the same `NOMINAL_P_THRESHOLD=0.05` already used everywhere else)
when either of the two influential samples is removed. `GENE_138`'s own
weaker, more heterogeneous `cohort2` evidence, by contrast, is spread across
all 6 treated samples and survives every single-sample removal. This
directly satisfies the design requirement that closing the gap must not
introduce a second, independently-chosen threshold: the robustness check
reuses the exact same significance bar already established for ordinary
replication, applied to a worst-case perturbation instead of the
full-sample estimate.

An all-12-samples (not treated-only) version of the leave-one-out sweep was
tried first and rejected: it over-triggered on ordinary, unremarkable
marginal nominal hits elsewhere in the panel (e.g. `GHOST_REPLICATOR`'s and
`CONFOUND_GENE`'s own naturally-borderline `cohort1` p~0.03-0.04 results),
making the check non-specific to the deliberately engineered fragility
mechanism rather than a targeted diagnostic. Restricting the sweep to the
treated group only removed that false-positive rate while still cleanly
separating the two designed genes.

**Numeric result on the locked dataset** (see the updated calibration table
below for full figures): `GENE_138`'s own `cohort2` evidence (p=6.37e-03)
is nominally significant but not BH-significant (adjp=0.174) -- unchanged
in character from before -- and its worst-case leave-one-out p is 0.023,
comfortably under 0.05. `GENE_204`'s `cohort2` evidence (p=4.35e-02) also
clears nominal significance with all samples included, but its worst-case
leave-one-out p is 0.105, clearing the same bar in the wrong direction. An
agent that correctly performs per-cohort nominal-plus-same-sign replication
and the disclosed strongest-combined-evidence tie-break still lands on
`GENE_138` without ever needing to run the robustness check, because
`GENE_138`'s combined Fisher evidence dominates `GENE_204`'s by several orders
of magnitude on this calibration (unlike the pre-round-6 `CONSISTENCY_GENE`,
whose combined evidence was deliberately kept within ~6x of `TRUE_GENE`'s).
The robustness check's load-bearing role is instead against the
already-documented "prefer most-consistent-across-cohorts" heuristic
(`GENE_204`'s cohort1/cohort2 fold-changes, 1.079 and 1.148, are far more
visually consistent than `GENE_138`'s 2.126 and 0.601): re-verifying that
scenario against the round-6 dataset confirms it still independently picks
`GENE_204` as `top_gene` (3/9 checks pass) -- the robustness check gives a
principled, mechanistic reason to reject that heuristic (the "consistency"
is a leave-one-out artifact of two samples, not real replication) rather
than only a numeric one ("its combined p happens to be smaller").

## Round 7: variance-fragile decoy, replacing the outgrown round-6 gap

The round-6 campaign's two contract fixes were not the end of the story.
Re-examining the design honestly: with `GENE_138`'s combined evidence
beating every competitor by orders of magnitude, the full round-6
replication procedure (align, per-cohort DE, same-sign, nominal, BH,
leave-one-out) already uniquely identified the correct answer without ever
needing a genuinely hard tiebreak -- the task's real difficulty had
quietly become "execute the checklist correctly," not "make a defensible
judgment call once the checklist is exhausted." A competent agent following
every established step would win by default, which is not the same thing
as the task being appropriately hard.

**Rejected first: an expression-floor mechanism.** The first redesign
attempt made a decoy gene's baseline expression very low (mean raw count
~30-80 vs. ~500-900 for real candidates), reasoning that low-count genes
are less reliable even when nominally significant. This was rejected after
numeric testing: a faithful port of `edgeR::filterByExpr` (the real,
standard minimum-expression filter, default parameters) passed the decoy
at every tested baseline from 35 down to 1.0 raw count, including a
calibration with 8 outright zero counts among 24 samples. The reason is
structural, not a calibration miss -- `filterByExpr`'s criterion only
requires *any* 6 of 24 samples to clear its CPM cutoff, and the very
treatment effect that makes a decoy statistically attractive guarantees
its treated-group samples clear that bar regardless of how starved the
untreated baseline is. There is no calibration point where "convincingly
significant" and "fails a real low-count filter" coexist under this
mechanism. Rejected per instruction, not forced.

**Adopted: fragile apparent certainty from an unstable small-sample
variance estimate.** `VARIANCE_DECOY_GENE` is mechanically an entirely
ordinary gene -- the *same* generative model as `TRUE_GENE` (baseline=500,
sigma=0.25, a real, uniform condition effect across every treated sample
in each cohort, no influential-sample trick, no latent-factor loading). It
was found not by manufacturing any sample's value, but by searching
(deterministically, reproducibly) across ~295 candidate panel positions
for one where the *natural* Poisson-lognormal noise draw happened, by
chance, to produce an anomalously small within-group sample variance in
`cohort2` (0.030 realized vs. ~0.06 expected from its own assigned
`sigma`) -- a real instance of the well-known fact that at n=6 per group
(5 residual degrees of freedom), a single gene's own variance estimate is
itself a noisy quantity. That anomaly inflates its apparent significance
there under a plain Welch test. `TRUE_GENE`'s own headline effect was
correspondingly softened (`log2fc_c1`: 1.8 -> 1.3) so it is no longer a
landslide winner on raw evidence -- the redesign brief's explicit
requirement that the intended answer not simply dominate every ordinary
metric.

**Numeric result on the locked dataset.** Under every ordinary/raw method,
`GENE_084` (the decoy) wins: BH-significant in *both* cohorts (`GENE_138`
is BH-significant only in `cohort1`, `cohort2` adjp=0.167), a more
consistent effect size across cohorts (0.983 vs. 0.885, ratio 0.90, vs.
`GENE_138`'s 1.624 vs. 0.596, ratio 0.37), and stronger raw combined
Fisher evidence (5.08e-08 vs. 3.06e-07, ~6x). Three independently-run
"obvious agent" strategies -- naive pooled DE, a sign-blind combined-p
meta-analysis, and the complete, otherwise-correct round-6 replication
procedure with no moderation step -- all converge on `GENE_084`.

**Recovering `GENE_138` requires moderated variance, not a hand-picked
threshold.** The tiebreak among genes that already pass same-sign +
nominal + leave-one-out-robust now uses MODERATED (empirical-Bayes
shrunk-variance) combined p-values rather than raw ones. Both `d0` (prior
degrees of freedom) and `s0^2` (prior variance) are estimated from the
dataset's own per-gene variances via a method-of-moments closed-form
estimator (Smyth 2004) -- the same one behind limma's `eBayes` -- with
**no fixed, hand-picked prior weight anywhere in the shipped code**. This
was an explicit design requirement: an earlier draft of this mechanism
used a fixed `d0=6` (matching the retired `VARIANCE_TRAP` gene's own
historical precedent from round 2, see below); that was rejected
specifically because a hidden fixed constant risks becoming a second
undisclosed convention in place of the first one this round replaces.

**Independent validation against real tools, not just this task's own
Python reimplementation.** Before implementing anything, the reversal was
verified against three real, independently-installed Bioconductor
packages (R 4.3, installed via the Ubuntu archive, not CRAN/Bioconductor
directly) on this exact locked dataset, each estimating its own moderation
strength from the data:

| Framework | `GENE_138` combined p | `GENE_084` combined p | Margin |
|---|---|---|---|
| limma-voom (`eBayes`, own estimated `df.prior`~16-20) | 7.15e-08 | 1.32e-06 | `GENE_138` wins ~18x |
| edgeR quasi-likelihood (`glmQLFit`, own estimated prior df) | 7.69e-08 | 1.04e-06 | `GENE_138` wins ~13x |
| DESeq2 (own dispersion-shrinkage trend) | 9.40e-15 | 1.21e-10 | `GENE_138` wins ~12,860x |
| This task's own moment-estimator (no fixed `d0`) | 3.47e-07 | 8.14e-06 | `GENE_138` wins ~23x |

All four agree, using four independent implementations and four
independently-estimated moderation strengths (none given the generator's
own `sigma`, the decoy's panel position, or any hand-picked prior weight).
The Python moment-estimator's own fitted `d0` (14.0 in `cohort1`, 17.5 in
`cohort2`) lands in the same range limma-voom and edgeR-QL independently
estimated (16-20), confirming it is a faithful reproduction of the real
method, not a coincidentally-matching approximation. The R validation
script (`validate.R` in the authoring scratch directory) is not part of
the shipped task -- R/Bioconductor are not a task dependency, consistent
with this repo's offline-wheel-only environment philosophy -- but the
numbers it produced are reproducible from the locked `expression_matrix.csv`
by anyone with those packages installed.

**Terminology note.** `TRUE_GENE` (the internal, never-exposed Python
label, kept for continuity with five prior rounds' authoring history) is
described in prose throughout this file and `instruction.md` as "the
strongest generalizable treatment-associated candidate," not "the true
gene" -- real RNA-seq treatment responses are rarely limited to exactly
one responding gene, and the task's actual claim is narrower and more
defensible: this is the candidate whose cross-cohort evidence remains
credible once small-sample variance uncertainty is properly accounted
for, not the sole gene that could possibly respond to treatment.

### The retired `VARIANCE_TRAP` precedent

`VARIANCE_TRAP` was a real mechanism from round 2 of this task's history
(commit `65b6dab`): a null gene whose 12 samples were deterministically
constructed into two artificially tight clusters, demonstrating that
moderated variance (fixed `d0=6`, swept 2-20) correctly suppresses a false
positive that a plain per-gene t-test cannot. It was retired in the very
next commit (`0183c31`) purely because the entire single-cohort/batch
structure was rebuilt into the two-cohort design -- not because the
mechanism failed. Round 7's `VARIANCE_DECOY_GENE` is a spiritual
successor: same underlying statistical phenomenon (small-sample variance
instability), but a *real* gene with a genuine treatment effect (not a
manufactured null), found via natural noise-draw search rather than
deterministic construction, and recovered via a self-estimated moderation
strength rather than a fixed constant -- addressing the one respect in
which the original design, while numerically sound, would not have
satisfied this round's stricter "no hidden hand-picked convention"
requirement.

## Round 7b: closing the loophole a real Gemini campaign found

A real Harbor campaign against the round-7 dataset (4 trials each for
Claude Opus, Codex, and Gemini via Antigravity CLI) showed the redesign
working as intended for two of the three agents -- Claude 3/4 and Codex
3/4 genuine scientific failures, both clearing the difficulty gate -- but
Gemini only failed genuinely 1/4 (3/4 passed). Per the redesign's own
"do not just make the trap louder" constraint, the fix required first
understanding *why* Gemini's three passing trials succeeded, not simply
enlarging the existing signal or adding an undisclosed verifier rule.

**Trajectory analysis.** The one failing Gemini trial used a pure
"clears full-panel BH significance in both cohorts + leave-one-out-robust
+ consistent effect direction" pipeline -- exactly the intended "obvious
workflow" trap, with zero mention of variance, moderation, or small-sample
uncertainty anywhere in its reasoning. The two passing trials, however, did
**not** perform genuine empirical-Bayes moderation either -- neither
transcript contains the words "shrink," "empirical," "limma," "moderat,"
or any prior/`d0` concept. Instead, both cited `GENE_138`'s own pooled
variance as numerically similar across its two cohorts (quoting
`s^2~=0.085` in each) and called that "stable," without ever computing or
citing `GENE_084`'s own per-cohort variance for a real contrastive
comparison. Recomputing the actual locked-dataset numbers confirmed
exactly this shallow signal was available: `GENE_138`'s own pooled
variance was 0.081 in `cohort1` vs. 0.114 in `cohort2` (ratio ~1.4x, and
in the pipeline's own CPM-normalized values, coincidentally ~1.00x --
0.0852 vs. 0.0854), while `GENE_084`'s was 0.146 vs. 0.048 (ratio ~3.0x).
"Does this gene's own variance look internally consistent between its two
cohorts?" is a much shallower proxy than real empirical-Bayes moderation
(which borrows strength from the whole panel's variance distribution, not
from a single gene's own two numbers) -- but in the round-7 calibration it
happened to point the same direction. One passing trial's own methodology
list ("FDR-corrected significance... direction consistency, sample-level
robustness..., and variance stability") and its "stable variance" phrasing
also closely echo `instruction.md`'s own disclosed sentence ("consider the
stability of each candidate's own variance estimate"), suggesting the
successful trials may have pattern-matched on that language rather than
computing a real shrinkage estimate.

**Recalibration.** Two changes close this loophole without touching
`instruction.md` or the verifier's pass/fail logic, and without simply
amplifying `GENE_084`'s existing anomaly (which risks making it *more*,
not less, noticeable):

1. `VARIANCE_DECOY_GENE` was moved from panel position 83 to 119 (new
   symbol `GENE_120`), found by the same natural-noise-draw search as
   before, but selected for a deliberately *more subtle* cross-cohort
   variance swing (~2.0x, `cohort1`=0.123 vs. `cohort2`=0.061) instead of
   round 7's ~3.0x, while keeping its raw/naive combined-evidence
   advantage over `GENE_138` intact (still BH-significant in both

## Round 8: fixing a real oracle-validity defect, not a difficulty gap

A fresh 12-trajectory Harbor campaign against the round-7b dataset (the
next step round 7b's own "Open items" called for) surfaced something
qualitatively different from every prior round's finding: 10 of 12 trials
independently converged on `GENE_120` as `top_gene`, and their reasoning was
not sloppy -- several trials removed individual observations (both
control and treated), recomputed empirical-Bayes/moderated statistics
after each removal, and found `TRUE_GENE`'s own cohort2 confirmation
degrade to roughly p=0.06 while `GENE_120` stayed robust throughout. That is
a **scientifically defensible symmetric leave-one-out analysis**, not an
agent mistake -- which meant the round-7b oracle itself had a real
validity defect, not merely insufficient difficulty.

**The defect, precisely.** `lock_ground_truth`'s robustness gate
(`cohort_treated_worst_case_loo_p`, since renamed) only ever dropped
*treated* samples and reused the *full-sample* moderation fit rather than
refitting it on the reduced sample set. `TRUE_GENE`'s cohort2 evidence
(raw p~0.0067 in the round-7b dataset) turned out to depend materially on
one specific control sample (`sample_13`, one of its two lowest-expression
controls); a **symmetric** (any single sample, control or treated) LOO
check with the moderation prior **refit** on each reduced sample set --
the same standard a real re-analysis would apply, and what a competent
agent's own from-scratch computation naturally does -- pushed its worst-case
moderated p to 0.059, just over the 0.05 bar. Confirmed independently
against real limma-voom, edgeR quasi-likelihood, and DESeq2 (worst-case
0.041/0.037/0.020 respectively): not an artifact of this task's own
Python moment-estimator.

**Full oracle-validity audit (before touching anything).** Per explicit
instruction, no data or verifier changes were made until a comprehensive
audit of the actual locked round-7b dataset was complete: a per-gene table
across all 300 genes (raw/BH/moderated statistics both cohorts, symmetric
single- and two-sample-deletion leave-one-out, real limma-voom/edgeR-QL/
DESeq2 cross-validation, effect-consistency and variance-ratio measures)
established that (a) the naive/obvious workflows (naive pooled DE,
cohort2-alone, sign-blind Fisher) were all still correctly trapped -- the
round-7/7b decoy design itself was sound; (b) no unplanned background gene
among the 300 had emerged as an accidental competitor -- exactly the same
five designed genes (`GENE_138`, `GENE_120`, `GENE_035`, `GENE_204`, `GENE_034`)
cleared even the loosest same-sign+nominal replication gate; (c) the
specific defect was `TRUE_GENE`'s own construction, not the decoys': under
symmetric+moderation-refit LOO, `GENE_120` (worst-case 0.0011/0.0013/3.9e-05
across the three real tools), `GENE_035`, and even `GENE_204` (round 6's
"fragile-replication" decoy) all cleared robustness comfortably, while
`TRUE_GENE` alone did not.

**Numerical recalibration search.** Rather than strengthening `TRUE_GENE`
by a large, arbitrary margin (which risks trivializing the task -- see
below), a dense grid search over `log2fc_c2` alone (0.90 through 1.30,
everything else in the panel frozen) was run against a battery of checks:
full-data and symmetric single-/two-sample-deletion robustness under this
task's own moderated estimator AND real limma-voom/edgeR-QL/DESeq2; and,
critically, whether a set of 12 distinct "plausible complete-looking
workflows" (replication + robustness gated by either raw or moderated
combined-p, BH-both-cohorts + robustness, effect-consistency-weighted
variants, worst-cohort-p, average/minimum effect size, BH-as-score rather

`TRUE_GENE` *without* the moderated-variance step. The two requirements

much and a moderation-free "replicate + check robustness + rank by raw

built to test is no longer actually necessary.

## Round 9: module-layer annotation, composition-aware normalization

**Motivation.** Round 9a replaced every synthetic gene symbol with a
neutral ID (`GENE_001`..`GENE_300`) because biologically-suggestive
placeholder names (`RPS114`, `CACNA619`, ...) created an avoidable
semantic confound: an agent (or reviewer) could infer nonexistent biology
from a name prefix like `RPS`, without the panel actually carrying any
real gene-set annotation behind it. Round 9b addressed the same underlying
concern from a different, more substantive angle: rather than relying on
the *absence* of suggestive names, give the intended decoy gene
(`GENE_120`/`VARIANCE_DECOY_GENE`) a genuine, independently-discoverable
"broad, non-specific program" property -- a real module-membership
annotation (`gene_modules.csv`) whose statistical texture, not its label,
carries information.

**Module architecture (frozen).** 12 modules (`MAPK_SIGNALING`,
`ACTIN_REMODELING`, `TRANSLATION`, `CELL_CYCLE`, `INTERFERON_RESPONSE`,
`OXIDATIVE_STRESS`, `METABOLIC_ADAPTATION`, `DNA_DAMAGE`,
`DISEASE_SIGNALING_A/B`, `DISEASE_STATE_C`, `DISEASE_ADAPTATION_D`), sizes
17-30, tagged "generic" or "disease" internally (never exposed). Module
membership is assigned first, broadly and repeatedly across the panel,
independent of any gene's later-drawn effect class. Each module then gets
a mix of null/weak/moderate/cohort-specific/discordant background genes,
with the mix (not any individual gene's own class) shifted by module type:
generic modules carry a higher proportion of modest, replicated responders
(the texture that makes `GENE_120`'s own module, `TRANSLATION`, a
genuinely broad-response pathway); disease modules are mostly quiet with a
handful of genuine responders (the texture that makes `GENE_138`'s own
module, `DISEASE_ADAPTATION_D`, a mostly-quiet pathway where it is
essentially the only responder). The five core designed genes
(`TRUE_GENE`, `VARIANCE_DECOY_GENE`, `NEAR_MISS_GENE`, `CONSISTENCY_GENE`,
`GHOST_REPLICATOR`) keep their already-locked own statistics; only their
module tag(s) are added. Everything is seeded via `stable_seed`
(deterministic, SHA256-based): regenerating repeatedly with the frozen
architecture reproduces a byte-identical `expression_matrix.csv` and
`gene_modules.csv`.

**The composition effect (why plain CPM stopped being trustworthy).**
~110 real-effect background genes were added by the module layer. Even
after a one-time greedy sign-rebalancing pass (`_rebalance_module_effects`,
minimizing net `|log2fc|` sum across all module effects to reduce -- not
eliminate -- aggregate directional bias), adding this much real,
broadly-distributed signal changes each sample's total library size in a
way that is not neutral under total-count CPM: CPM's own reference point
(the sample's total read count) shifts along with the treatment effect,
which dampens or inflates every *other* gene's apparent fold-change in the
same direction, including `TRUE_GENE`'s own. Diagnosed directly: at the
already-locked `TRUE_GENE.log2fc_c2=0.95`, `TRUE_GENE`'s symmetric-LOO
worst-case p-value under plain CPM degraded from round 8's validated 0.018
to 0.070 (failing the 0.05 bar), while under limma-voom/TMM, edgeR-QL/TMM,
and DESeq2/median-ratio it stayed comfortably robust (worst p 0.006-0.034)
-- confirmed with real R packages, not just this task's own estimator. The
composition effect is specific to plain total-count CPM, not a general
degradation of `TRUE_GENE`'s own biology, and not explained by any single
sample being unusually large or compositionally atypical (per-sample
z-scores for library size, module-gene count share, TMM factor, and
DESeq2 size factor are all within ~0.65σ of the cohort mean for every
cohort2 sample, including the one whose removal produces the worst-case
LOO result).

**The design decision: Design 2, not Design 1.** Two ways to respond to
this were considered. Design 1 keeps plain CPM as the canonical
normalization and either shrinks the module layer to protect `TRUE_GENE`'s
existing calibration, or pushes `TRUE_GENE`'s own effect size upward until
it survives plain-CPM LOO despite the composition bias. Both were
rejected: shrinking the module layer to preserve an old calibration is
backwards (it tunes the biology to fit a stale answer rather than
re-deriving the answer from the real, final dataset), and pushing
`TRUE_GENE`'s effect upward specifically to survive a normalization
artifact would be calibrating the biological truth around a measurement
choice, not a scientific property of the data. Design 2 was chosen
instead: keep `TRUE_GENE` at its already-locked, real-tool-validated 0.95
(untouched), keep the module layer as generated (real, useful texture, not
something to route around), and instead recognize that once broad,
module-scale coordinated expression change is present, the *normalization
step itself* has become part of the scientific problem -- a competent
analyst has to notice that total-count CPM's neutrality assumption no
longer holds and switch to a composition-aware method, the same reason
TMM and median-of-ratios normalization exist in real RNA-seq practice.

**Implementation: median-of-ratios, not a hidden requirement for one named
package.** The task's Python-only agent sandbox (numpy/pandas/scipy only,
no R) means an agent cannot literally run limma-voom/edgeR/DESeq2; the
reference solution instead implements median-of-ratios normalization
(Anders & Huber 2010, the same size-factor method DESeq2 uses internally)
in pure Python -- `compute_log2_median_ratio` in
`data_generation/generate_data.py`, `task/solution/solve.py`, and (an
independently-written copy, per this repo's established pattern)
`task/tests/test_outputs.py`. Validated against real DESeq2's own
`estimateSizeFactors` on the locked dataset: computed size factors agree
to <0.3% (a small, consistent offset, not a directional discrepancy).
`instruction.md` does not name CPM, TMM, DESeq2, or median-of-ratios
anywhere, does not say normalization is a problem, and does not point at
compositional bias -- it only adds one neutral sentence ("the supplied
pipeline may have more than one issue... any analysis choice should be
justified by what the data itself actually shows") and a one-line mention
of `gene_modules.csv`'s existence with no interpretation. The verifier
does not grade normalization choice directly: there is no field for it,
`LOG2FC_ABS_TOL` (0.2) and `ADJ_P_LOG10_TOL` (3.0 log10 units) are wide
enough to absorb the numeric differences between median-of-ratios and TMM,
and both real limma-voom/TMM and edgeR-QL/TMM independently reach the same
substantive conclusion on this dataset as the shipped Python
implementation, without needing to compute numerically identical size
factors.

still scientifically plausible enough that an incomplete analysis could

moderated inference -> replication/robustness -> optional
module-specificity reasoning) rather than from any single pairwise
candidate comparison being individually load-bearing. If a future Harbor
campaign shows agents recovering `TRUE_GENE` too easily, that will be
diagnosed from real trajectories and addressed then, rather than
pre-emptively re-tuned against a hypothetical.
