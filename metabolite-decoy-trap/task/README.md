# Scientific task maintainer notes

## Data provenance

All three public tables (`pk_concentrations.csv`, `pd_response.csv`,
`subjects.csv`, identical copies in `environment/data/` and `tests/data/`) are
synthetic, generated by `../data_generation/generate_data.py` (deterministic,
no external network dependency). That script also writes
`../data_generation/private/subjects_ground_truth.csv`, an authoring-only
file carrying the true continuous-profile AUCs and the hidden covariate value
per subject; it is **not** copied into `environment/data/`, `tests/data/`, or
either Docker build context, and must never be. It exists purely so a
reviewer can audit that the task's intended relationship is real and not an
artifact of noise.

Two real bugs in the originally-drafted generator were found and fixed during
authoring, both confirmed by direct inspection of the regenerated output:

1. The single-dose cohort's PK sampling window was computed as
   `t_end = n_doses * tau_hr`, which evaluates to `1 * 0 = 0` for single-dose
   subjects (`tau_hr` is a placeholder there), silently producing zero PK
   concentration rows for all single-dose subjects. Fixed to
   `t_end = (n_doses - 1) * tau_hr + obs_end`, matching the window actually
   simulated.
2. Subject-level RNG seeds were derived via Python's built-in `hash()` on
   strings, which is randomized per-process (`PYTHONHASHSEED`) unless fixed,
   so the "same" script produced different data on every run. Replaced with a
   `hashlib.sha256`-based deterministic seed. Verified: two consecutive runs
   now produce byte-identical CSVs (`md5sum` match).

After both fixes, the intended hard negative (M2 competitive with M1 in the
single-dose cohort, M1 dominant in the multi-dose steady-state cohort) did
**not** reproduce — under the original PD parameters (`EC50_AUC_M1=140`,
`HILL=1.3`), M1 beat both M2 and parent in every cohort, under raw and
dose-adjusted correlation, across 6+ independent seeds and 4 sample sizes.
The originally-reported correlation table in the authoring brief was an
artifact of the two bugs above, not a real property of the mechanism.

The PD curve was retuned (`EC50_AUC_M1: 140 -> 300`, `HILL: 1.3 -> 3.0`) so
M1's pharmacodynamic effect only engages once exposure crosses a threshold a
single dose does not reach but steady-state repeat dosing does — a real,
common PK/PD pattern (effects that require accumulation). This reproduces the
intended trap robustly: across 6 independent seeds at the shipped sample size
(n=10/dose level), single-dose correlations are M1 approx -0.16 to +0.07
(indistinguishable from noise), M2 approx +0.08 to +0.24 (a real, if modest,
edge); multi-dose steady-state correlations are M1 approx 0.83-0.94, clearly
ahead of parent (approx 0.83-0.89) and M2 (approx 0.63-0.74) in every draw.
Naive full pooling (ignoring cohort/regimen) gives M1 0.439 vs. parent 0.412
vs. M2 0.074 on the shipped dataset — pooling correctly rules out M2 but does
not confidently separate M1 from parent, so it is not a viable shortcut
either.

Re-run the generator to reproduce: `python3 data_generation/generate_data.py`
from the project root writes `data_generation/public/*.csv` (copy these into
`environment/data/` and `tests/data/`) and
`data_generation/private/subjects_ground_truth.csv` (authoring-only, never
ships).

## Container contract

The runtime Dockerfile builds explicitly for Linux/amd64, copies only
`environment/data/`, creates the non-root `agent` user, and has no networked
package or agent-bootstrap step at runtime. `environment/wheels/` vendors
both the solution's runtime dependencies (`numpy==2.1.3`, `pandas==2.2.3`,
and their transitive deps) and the verifier's dependencies (`pytest==8.4.1`,
`pytest-json-ctrf==0.3.5`, and transitive deps), since the Nexus sandbox runs
one shared image for both the agent and the verifier and ignores
`[verifier].environment_mode`. `tests/wheels/` carries the same combined set
for the optional local two-image `tests/Dockerfile` fixture, which is not
used by submission.

## Solution and verifier design

`solution/solve.py` computes each subject's per-analyte AUC via the
trapezoidal rule over the visible sparse concentration samples, splits
subjects by dosing regimen (`n_doses == 1` vs. `n_doses > 1`, not by the
`cohort` label string), computes each candidate's Pearson correlation with PD
response within each regimen, and nominates the species whose correlation is
strongest in the multi-dose steady-state regimen.

`tests/test_outputs.py` independently recomputes the same AUC/correlation
pipeline from its own copy of the data (`tests/data/`, byte-identical to
`environment/data/`) and checks:

- schema/finite-value validity of `result.json`;
- the nominated species' recomputed multi-dose association exceeds every
  other candidate's by at least 0.04 (a relative-dominance check against the
  verifier's own recomputation, not a fixed absolute correlation cutoff —
  chosen well below the ~0.06-0.11 margin observed across seeds during
  authoring, so it tolerates a reasonable alternative AUC methodology while
  still rejecting a wrong nomination);
- the agent's reported `single_dose_association` / `multi_dose_association`
  values for the nominated species are within 0.20 of the independent
  recomputation (an integrity check against fabricated or copy-pasted
  numbers).

Manually verified both failure directions: a `"M2"` nomination and a
`"parent"` nomination each fail the dominance test (multi-dose margins of
-0.27 and -0.10 respectively against the recomputed values), while the
Oracle's `"M1"` nomination passes all three tests.

## Local commands

From the repository root:

```bash
python3 scripts/validate_scaffold.py
./harbor_runner.py task --no-remote --smoke-test
```

For a fast authoring check with an already-installed host agent, run one local
trial without Workbench or Modal:

```bash
./harbor_runner.py task --quick --quick-agent codex   # or claude
```

Quick evidence is kept under `harbor-jobs/` and
`trajectories/quick/<run-id>/`; it is separate from the three-agent campaign
archive.

To verify the vendored dependencies without an index:

```bash
python3 .agents/skills/task-fixer/scripts/vendor_offline_dependencies.py \
  --task task --out task/environment/wheels --python-version 3.12 --verify
python3 .agents/skills/task-fixer/scripts/vendor_offline_dependencies.py \
  --task task --out task/tests/wheels --python-version 3.12 --verify
```

After a successful multi-agent run, the vendored runner writes its Oracle,
agent trajectories, and combined summary directly under the project-level
`trajectories/` folder. Run the trajectory review described in the root
`README.md` against that folder.
