# lipophilic-efficiency-trap: maintainer notes

Optional maintainer notes for this task. Not shipped to the agent.

## Design summary

A hit-to-lead SAR dataset for a fictional kinase target ("Kinase X"), 28
analogs from one scaffold. The task asks the agent to nominate a single
compound to progress, from raw replicate potency assays (with QC-flagged
failed replicates that must be excluded) and ADME/physicochemical
descriptors.

The core trap is a realistic, well-documented med-chem confound:
lipophilicity (`clogp`) genuinely contributes to on-target potency (filling
a hydrophobic pocket) but drives off-target potency almost entirely (the
off-target pocket has different geometry, so it rewards nonspecific
lipophilic binding but not the on-target-specific SAR component). The
single most potent compound by raw pIC50 is therefore the most lipophilic,
and correspondingly fails the developability gate (poor metabolic
stability, poor permeability). See `solution/process.md` for the full
generative mechanism and validated numbers.

## Data provenance

Generated by `data_generation/generate_data.py` (deterministic,
`hashlib.sha256`-seeded per compound/assay). Key generative constants and
their rationale:

- `TARGET_LOGP_WEIGHT = 0.25` vs. `OFFTARGET_LOGP_WEIGHT = 0.55`: lipophilic
  binding contributes to on-target potency but dominates off-target
  potency -- this asymmetry is what makes `selectivity_index` isolate
  genuine SAR.
- `ASSAY_REPLICATE_NOISE_SD = 0.06`: tuned empirically (not assumed) so the
  gate-passing compounds separate by a comfortable margin in `lle`
  (0.16 log units between the top two) after 3-replicate QC-filtered
  averaging. An earlier value of 0.15 (a more typical raw single-replicate
  assay reproducibility figure) produced gate-passer margins as thin as
  0.03 log units after averaging -- too close to call reliably against any
  reasonable recomputation tolerance, so it was tightened. This is the one
  parameter tuned specifically for margin robustness rather than domain
  realism; 0.06 log units (~15% CV) is still within the range of a
  well-optimized biochemical assay.
- Developability thresholds (`solubility_um >= 20`, `clint_ul_min_mg <=
  45`, `papp_1e6cm_s >= 8`) and the selectivity threshold
  (`selectivity_index >= 0.6`, i.e. ~4-fold) are standard, disclosed
  literature-typical hit-to-lead triage bars, not reverse-engineered from
  the dataset to hit a particular answer -- the answer emerged from the
  generative mechanism, not from picking a threshold that produces it.

## Solution and verifier design

- `compound_metrics.csv` tolerances: 1% relative (0.02 absolute floor) --
  every derived field is simple arithmetic on clean, already-averaged
  inputs, not a numerical approximation, so a materially different method
  should not pass.
- `result.json` aggregate tolerance: 0.03 absolute.
- `nominated_lead_id` is checked by exact string match against the
  verifier's own independent recomputation -- a discrete correctness check
  with no statistical margin to tune, unlike a correlation-based dominance
  check. Manually verified both the naive-potency decoy (C022, fails the
  developability gate) and the runner-up gate-passer (C028, 0.16 lle units
  behind) fail this check when substituted for the correct answer.

## Known constraint: Docker Hub CDN egress

This sandbox's egress policy blocks Docker Hub's CDN, so both Dockerfiles
pull from `mirror.gcr.io/library/python:3.12-slim` instead of
`python:3.12-slim` directly (confirmed byte-identical via matching manifest
digest to the upstream image).
